## Evidence provenance and limitations

Extraction retained **4,413 full-resolution JPEG samples**, **4,236 OCR
records**, **177 unchanged-chat skips**, **95 ten-second contact sheets** and
**370 two-minute overview samples**. OCR skips do not skip the video image.

Local evidence is retained in this session's
`files\video-survey\<slug>` directories:

- `frames\sNNNNN.jpg`: N is the sampled second in the original video.
- `ocr.jsonl`: raw OCR records, including explicit unchanged-chat entries.
- `transcript.txt`: deduplicated, timestamped chat text.
- `mechanics-extract.txt`: filtered leads, not a trusted game-event log.
- `sheets\sheetNNN.jpg`: 48 consecutive ten-second samples per sheet.
- `overviewNN.jpg`: two-minute overview.
- `coverage.json`: actual extraction counts and endpoints.

Session evidence root:
`C:\Users\nukec\.copilot\session-state\4b383529-0e1a-494e-b30d-d423a61e4716\files\video-survey`.
Slugs are `overseer`, `medical`, `captain`, `genetic-ai`, `pilot-alien`,
`pilot-second`, `pilot-ruin`, `science`. Reports are repository deliverables;
session images are local supporting evidence, not portable repository assets.

The extractor uses ten-second target seeks plus a near-end integer-second
sample. OpenCV/FFmpeg seeking was used, not frame-index enumeration or
presentation-timestamp certification. Windows OCR covered the fixed right
chat crop; popup windows elsewhere are often absent from the transcript.
Cached early OCR used different image scaling from the final two-times
sharpened pass. Exact/alphanumeric deduplication and a small recent-line window
reduce repeats but cannot identify semantic event duplicates.

Consequences:

- An evidence time means **visible at that position**, not exact onset.
- Old scrollback can coexist with new actions, successes and failures.
- OCR confuses letters/digits and misses wrapped lines, names and fast chat.
- Dialogue is not a demonstrated mechanic; titles are not demonstrated events.
- Effect source, duration and sound cannot be recovered from a lone JPEG.
- A name search finding no match does not prove no differently named
  implementation exists. Missing classifications are bounded to examined
  production surfaces; generic counterparts are listed explicitly.
- Exact numerical behavior requires multiple direct action observations or
  authoritative original source, not inferred tuning.

## Status legend

- **Present foundation**: real production implementation exists; source-perfect
  behavior, placement and values are not automatically verified.
- **Partial**: name/art/general system exists but recorded contract differs.
- **Missing source contract**: examined production sources lack a specific
  directly observed surface/state machine.
- **Unverified**: evidence or code linkage is insufficient to conclude.

**V** in ledgers means full-resolution visual inspection. **O** means an OCR
lead. Imported sprite state names are asset candidates, not match certificates.
No status here means that live in-game parity has been validated.

## Implementation dependencies, not a claim of implementation

1. **Recover evidence contracts first:** dense popup/action review for research,
   genotype, psychocorrection, Scout destinations and afterlife. Preserve
   unresolved rules rather than invent them.
2. **Authored data:** named technology/software dependency graph, genotype
   sequence mapping, document/suspect relationships, destination templates.
3. **Wire existing foundations:** real shuttle controller, disk/research
   lifecycle, shared storage, surgery/organ state, clone records and AI minds.
4. **Implement missing interactions:** charged Medi-Kit, diagnostic/search
   surfaces, trigger/subpersonality, guardians/lockout, source afterlife.
5. **Map/loadout and presentation:** exact physical layouts, objects, access,
   directional/held/worn sprites, animation/effect and sound bindings.
6. **Manual acceptance:** verify prerequisite -> action -> committed state ->
   interruption/failure -> persistence, not just a matching chat string.

## Remaining exhaustive-review backlog

The requested **every single parity gap, all mechanics/objects/effects** cannot
be certified by the completed sampled pass. Remaining work includes:

- Enumerate/review decoded frames with presentation timestamps, without
  confusing nominal fps with game ticks; retain a coverage ledger per interval.
- Densely inspect every interaction window, including all menus outside the
  OCR crop, and track exact action prerequisites/results.
- Identify unexamined decorations, props, bodies, held/worn states and map
  coordinates rather than assigning types from silhouettes alone.
- Measure transient effects with start/end frames, affected viewport/plane,
  camera movement, lighting, overlap and interrupt behavior.
- Review audible events locally and distinguish game cues from edited music,
  recording artifacts and spoken dialogue.
- Resolve player-controlled versus autonomous entities and edited/continuous
  scene transitions, especially later RUIN and AI-restoration footage.
- Compare runtime behavior in the actual project. No live Dream Seeker
  acceptance session was performed for this audit.

The reports intentionally record these limits. They must not be used to
declare perfect parity or turn uncertain OCR/dialogue into invented mechanics.
