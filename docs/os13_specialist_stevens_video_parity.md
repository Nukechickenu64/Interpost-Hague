# Specialist Stevens: video survey and cyberspace parity

## Source and coverage

Source: `Orbital Station 13 - Specialist Stevens - D4n0w4r (1080p, h264).mp4`.
Local file: 917,517,171 bytes; 1920 x 1080; 30 fps; duration
**02:53:26.567** (10,406.567 seconds).

The complete runtime was surveyed using **347 thirty-second samples** in
15 contact sheets. The sheet labels identify thirty-second slots, not exact
event boundaries: FFmpeg's `fps=1/30` filter selects a representative frame
within each interval. Exact-time detail frames were separately sought at the
timestamps cited below. Two interaction sequences, 00:15:38-00:15:56 and
00:19:05-00:19:35, were additionally sampled at one frame per second.
Those sequence frames represent approximately each interval's midpoint.
The final second was also inspected at full resolution.

This is a **whole-runtime visual survey with focused cyberspace analysis**,
not an exhaustive frame-by-frame or audio transcript. Short actions between
samples, off-screen console use, narration and every chat line have not been
recovered. No claim of perfect gameplay parity is justified by this coverage.
Video and extracted frames remain local; they were not uploaded.

Evidence frames and sheets are retained in the session's
`files/stevens-survey` directory. `detail-<seconds>.jpg` names exact requested
seek times. `survey-0001.jpg` through `survey-0347.jpg` are the coarse samples;
`pickup-*` and `finish-*` are the two one-second sequences. The latter name is
an extraction label, **not** a claim that the first attempt succeeded.

## Implementation contract

The earlier implementation used a randomized narrow maze, hexadecimal
relay input dialogs and a separate timed core download. That is not the
collection loop shown here.

The OS13 reconstruction replaces that objective with distributed collectible
data, a DATA LEFT readout and automatic physical-disk completion/return
after the last collectible. Other maps retain their relay/core objective.
Existing disk reservation, overwrite confirmation, success-only write,
mind return, power/link checks and normal Replicator-console import remain
authoritative. The later
[wiki-only catalogue integration](os13_extended_science_audit.md#implemented-wiki-only-catalogue)
replaces the generic discipline/level payload on OS13 with named technologies
and their four extraction tiers. It does not imply implementation of every
named technology's equipment or software effects.

Implemented OS13-only behavior:

- Open grid fields with separated, solid ICE islands replace the narrow
  relay maze. Two-cell gaps between the possible one/two-cell island widths
  preserve connected navigation. The entry and all objectives are on floor.
- Ten distinct data objects use the supplied OS13 `data` animation. Clicking
  from an adjacent tile or stepping onto one collects it exactly once.
- Each nonfinal collection reports DATA LEFT and refreshes the console
  readout. The avatar status panel and console show remaining data instead
  of relays; boot instructions and UI footer describe the correct objective.
- The final collection invokes the existing validated completion/write path
  directly, with no hex input or extra core download, and returns control
  to the physical body.
- The entry portal can be clicked or stepped onto to recall an incomplete
  dive. Initial avatar creation occurs during boot and does not trigger a
  running-session recall.
- Red ICE uses existing damage and art, distributed away from the entry
  and objective tiles. All node interaction remains bound to the owning
  generation and the actual live avatar/session.
- The archived Cybertechnician wiki explicitly says LMB deactivates Blue ICE.
  OS13 avatars can now left-click an adjacent interior ICE barrier to replace
  it with grid floor. The new floor is registered with the owning archive so
  release restores it to a wall; another dive does not inherit the opening.
  The outer boundary remains sealed and refuses deactivation with a notice.
  Boot instructions explain the interaction.

Barrier removal checks collection mode, current console/instance ownership,
the live avatar/mind/media/link/deadline validation, adjacency, archive z-level
and interior cell coordinates before changing terrain. It does not award data,
write a disk or alter the selected technology. Clicking again on the resulting
floor cannot collect a second reward or reopen a wall.

The boundary rule, adjacent reach and immediate removal with the existing
ICE-Pick sound are local reconstruction choices. This implements the wiki's
basic Blue ICE interaction, not full installed ICE-Pick software: cooldowns,
MK2 speed, removal of data/exit nodes, trapped data and advanced-port phasing
remain unimplemented. Blue ICE removal does not change red ICE behavior;
its current integrity damage still differs from the wiki's security escalation.
An additional console-UI hint could not be applied because Windows locked
the renderer file; the existing UI objective text is otherwise unchanged.

**Explicit local choices:** ten data objects per dive, adjacent-click and
step collection, island placement probability 65%, one/two-cell island
dimensions with four-cell spacing, existing level-based field dimensions,
red-ICE count twice the local research level and existing 20-integrity
contact damage. These values are not certified source tuning. Data is
deliberately reachable without an unimplemented ICE-Pick. Partial collections
still reset when the current local dive is released; the source's apparent
cross-attempt progress remains a known difference. Scanner, static fields,
Creators and guardian AI are not added as decorative placeholders.

Geometry, pickup input, number of data objects and any software/hazard tuning
must be called local reconstruction choices unless measured directly.
No exact original layout, random seed or section size can be recovered
from this survey alone.

## Validation and manual acceptance

### Recall and asynchronous interaction cleanup

Non-OS13 relay prompts and timed core downloads now stop if their node was
deleted during the wait. The core clears its working flag before attempting
completion, because successful completion deletes the archive's nodes.
Existing generation/session validation still governs any delayed result.
OS13 portal examination now describes both adjacent clicking and stepping
onto the portal; other maps retain their click-only description.

These are local lifecycle and guidance corrections, not additional recovered
source mechanics. Manual checks (not performed): recall while a relay prompt
or core download is pending, reuse the archive, and finish the old prompt.
The later session must not gain progress or write media. Normal core
completion must return the operator without accessing a deleted node.
Examine the return portal on both map modes and compare its instructions.

The previously blocked avatar-to-console ownership checks are now implemented:
Recall/EJECT, death, deletion and status display require the console's current
`dive_body` to be that exact avatar. A stale avatar cannot end a newer dive or
read its progress. Current-avatar emergency recall deliberately does not
require a healthy link/deadline, so broken sessions can still be cleaned up.
The wiki-only catalogue pass also completed Boot action identity checks.

Manual Blue ICE and ownership checks (not performed):

1. In OS13 cyberspace, left-click an adjacent island wall. It should become
   traversable grid floor with one notice/sound, without changing DATA LEFT,
   disk contents or research. Repeat on the same resulting floor.
2. Try a distant barrier, another archive's barrier, the outer boundary and
   a broken/expired session. None may change terrain. The outer boundary
   should explain how to leave.
3. Recall or finish after removing barriers, then reuse the slot. Cleared
   terrain must not survive release, and new objectives remain reachable.
4. Verify a non-OS13 relay maze has no wall-removal ability and retains its
   existing relay/core objective.
5. Retain a stale avatar reference while starting a newer dive. Recall,
   death, deletion and status display through the old avatar must not end
   or expose the new session. Current-avatar Recall/EJECT must still return
   the operator, including when its link is broken or deadline expired.

Validation must not launch Dream Maker or its compiler and must not run or
create unit tests. Use focused static inspection and whitespace checks.
No live in-game verification has been performed.

Completed checks:

- Static inspection of OS13/non-OS13 generation branches, connected-lane
  geometry, distinct objective placement, once-only collection guard,
  session/generation ownership, final write and recall cleanup.
- DMI metadata inspection confirms `data`, `ice`, `red_ice` and `tnc_exit`
  exist in the supplied OS13 sheet.
- Focused `git diff --check` passes for the changed production files and
  tracked audit; the new report was separately checked for trailing
  whitespace. No new dependencies were installed.
- The persisted survey contains 347 coarse frames and 15 overview sheets.

Manual checks for the OS13 collection reconstruction:

1. Boot a legitimate OS13 dive. Confirm the field has distributed data,
   uses supplied OS13 sprites and does not create hex relays or a core.
2. Verify all objectives are reachable without crossing solid ICE; no
   collectible overlaps the entry portal or another objective/hazard.
3. Collect a data object: progress advances exactly once, its visual target
   disappears, and the media drive still displays the old committed data.
4. Collect the last object: one completion writes the pending independent
   technology datum, returns the mind/body and releases chair/archive.
   Import the physical disk at the Replicator console normally.
5. Recall, enter the return portal, disconnect, remove power or break the
   neural link with incomplete data: no pending technology is committed.
6. Reuse an archive with a different operator. Old nodes/references must not
   grant progress or write a later session's disk.
7. On non-Alpha maps, verify the existing hexadecimal relay objective and
   core download remain unchanged, including existing status text.

Perfect parity is **not certified**. The unsupported mechanics above are
remaining work, not implied implementations.
